## 1. Prerequisites

- A verified Milele business account — [activate your account](https://milele.co.ke).
- Your **API credentials** (uuid + key) from the Milele dashboard.
- A tool to make HTTPS requests (e.g. `curl`, Postman, or an HTTP client in your language).

All requests must be made over **HTTPS** and include a valid `Authorization` header.
See [Authorization](/prerequisites/authorization) for full details.

```
Base URL:      https://api.milele.co.ke
Version:       /v1 — all endpoints are versioned in the path (e.g. /v1/balance)
```

See [API versioning](/prerequisites/versioning) for how versions are managed and when deprecated versions are retired.

---

## 2. Get your API key

1. Sign in to the [Milele dashboard](https://milele.co.ke/dashboard).
2. Navigate to **Developers / API keys**.
3. Create a key pair and copy:
   - **Consumer UUID** — identifies your integration.
   - **Consumer Key** — your API key.
4. Store them securely; treat them like a password.

You will exchange them for a short-lived bearer token:

```
Authorization: Bearer {access_token}
```

See the [Authorization](/prerequisites/authorization) guide for the token exchange flow.

---

## 3. Make your first request

The fastest way to confirm your integration is to retrieve your current balance.

```bash
curl -X GET https://api.milele.co.ke/v1/balance \
  -H "Authorization: Bearer {token}"
```

```json
{
  "status":   20,
  "amount":   10.0,
  "currency": "KES"
}
```

- `status: 20` means success — see [Status Codes](/status).
- `amount` is your available balance in the given `currency`.

---

## 4. Accept your first payment

1. **Create a payment** with the customer details and amount.
2. The customer receives an **STK push** (or equivalent prompt) to complete payment.
3. **Receive a webhook** from Milele with the final status.
4. Optionally **poll the status** endpoint for an immediate update.

Follow the [Accept a Payment](/payments/accept) guide for a full walkthrough.

---

## 5. Handle webhooks and errors

Use the [webhook](/webhooks) to learn the transaction's final status. While the status is pending or unknown, [check the existing transaction by ID](/core/status).

Use the `status` field to decide how to update your system.

| Status | Meaning |
|--------|---------|
| `20` | Success — payment complete |
| `0`, `3`, `31`, `100`, `101`, `202`, `203`, `204` | Pending |
| Listed as [Failed](/status#failed) | Failed — review and handle |

Only statuses listed as [Failed](/status#failed) are failures. Never resend a pending or unknown transaction with a new idempotency key.
